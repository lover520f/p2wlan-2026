# 多房间并行联网

## 本次实现范围

在好友房间 #71 的服务端授权与房间身份基础上，Windows、macOS、Linux 使用每房间独立 daemon 与 TUN。个人网络仍由主运行时管理。打开第二个房间不覆盖全局 networkId，不停止第一个房间。Android/iOS 保留原有能力：Android 仍为单活动网络，iOS 以既有平台能力为准；本改动没有实现移动端多房分流，不能据此声明全平台并行联网。

## 资源隔离

`ParallelRoomPlan` 复用以控制面、账号、房间生成的 SHA-256 Profile 标识。每房间有独立配置、设备身份、诊断凭证、PID、日志、诊断端口和 UDP socket。接口名称为 `p2r` 加 12 位 Profile 摘要，macOS 使用内核实际分配的 utun 接口。UDP 端口由内核分配；诊断端口由 Profile 确定，同客户端的资源碰撞在启动前拒绝，不允许复用别的房间或个人网络。

默认最多连接 8 个房间，避免无限创建进程与网卡。每个房间保留既有控制面与端到端加密会话，不新增房间间桥接能力。现有 RoomAuthorization 的最长 30 秒租期与入出站地址授权继续生效。

## 生命周期与界面

`ParallelRooms` 对同房间串行化连接/断开，跨房间独立运行。启动时保留运行时所有权；登录信息变化使旧启动请求失效并清理旧会话。停止失败不会删除运行时记录或伪报已关闭。全部关闭期间保持连接准入关闭直到主网络也结束。

房间页面连接/断开操作不再改写全局网络设置。旧的单活动房间可迁移为独立运行时。托盘按房间展示地址和状态，支持单房断开和全部停止。退出登录及应用主动退出必须先完成网络停止；隐藏窗口不停止网络。

GUI 恢复通过当前控制面的成员列表检查已有 Profile 与诊断凭证，只接管已存在的运行时，不自动启动所有加入的房间。状态刷新验证房间 ID、设备地址与本机路由；失败时清空快照并显示不可用，不用过期快照声称在线。

## 进程和路由安全

PID 查找和清理要求运行进程的精确 `--log-file` 参数与当前实例匹配；拒绝重复日志参数、其他房间日志和 build-info 探测进程。Windows 跨完整性级别看不到命令行时，回退只接受本次启动返回或经实例认证的 PID，不扫描并终止所有同名进程。

启动前读取 Linux 所有 IPv4 路由表、Windows IPv4 路由或 macOS IPv4 netstat 表。对其他 LAN、VPN、大网段及主机路由做真实范围重叠检查；默认路由除外。只可豁免经当前实例认证的接口。解析失败、超时或权限错误一律拒绝启动，不假定无冲突。本机路由在检查后仍可能被其他程序修改，实际并发改路由场景还需要端到端验证。

## 验证边界及发布门槛

新增 18 个生命周期/身份测试与 8 个原生路由表解析测试。mock 生命周期验证的是管理器时序，不是虚拟网卡或 P2P/Relay 真连通。三桌面系统 CI 运行新增测试，既有 Rust、Go、Flutter、安全及平台门禁不降级。临时离线分析工具导出已从最终工作流移除。

合并发布前还需验证至少以下场景并记录准确提交与结果：

- 同一主机两个房间同时传输；停止、被踢、改址或重连其中一个时另一个持续通信；个人网络可并存。
- 真实 TUN/路由、源地址选择、Direct 与 Relay；超期和撤销后不能继续使用缓存连接；跨房间转发默认拒绝。
- Windows UAC、macOS 提权与 Linux 权限流程；路径含空格/中文；不可读进程命令行；诊断端口被第三方占用。
- GUI 崩溃后控制面不可用或成员资格已撤销的残留进程恢复与清理。当前恢复依赖成员列表，不能将这一组合场景视为已经完整解决。
- 运行中的主网络配置变更、重新打开 GUI、多客户端实例竞争启动同一 Profile，以及本机路由动态变化。
