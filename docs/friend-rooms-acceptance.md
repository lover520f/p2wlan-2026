# 好友房间：实现约束与验收标准

状态：开发中。本文不是已完成、测试通过或可发布的声明。

## 产品范围

账号最多拥有一个有效房间，可以加入多个房间。房主创建房间后获得房间号及服务器分配的专属 IPv4 网段；成员通过房间号和密码，或可撤销且有限有效期的邀请凭证加入。原有个人网络必须保留，不能因加入房间而移动、删除或公开原有设备。

成员资格与同时联网是两个独立能力。仅支持在多个成员资格之间切换，不等同于多房间同时联网，界面、文档、PR 和发布说明必须明确区分。没有对应数据面与平台路由测试，不得声明支持多房间同时在线。

## 地址与身份

房间使用私有地址池内的独立 /24。建议默认池为 10.21.0.0/16，优先使用 10.21.1.0/24、10.21.2.0/24 等。20.21.3.0/24 不在本功能的可分配地址范围。

分配器必须检查所有现存网络的地址范围是否重叠，而不只是比较 CIDR 字符串。服务端在事务内分配网段并建立房主成员关系；唯一约束和并发重试共同保证每账号一个有效房间、每有效房间一个不冲突网段。地址池耗尽时返回明确错误，不复用仍在使用的网段。

唯一性范围是同一个控制面及其数据库。不同独立服务器之间不能宣称全局地址唯一；客户端必须对本机已有网络、其他 VPN 或其他控制面产生的路由冲突进行检测并拒绝不安全的配置。

房间 IP 按设备而非仅按账号分配。多设备账号的各设备必须拥有不同地址。拒绝网段外地址、网络地址、广播地址以及已占用地址。修改 IP 必须与旧凭证和连接撤销保持一致，不能只修改界面显示。

## 权限与撤销

所有房间管理接口要求账号认证；房主身份在服务器核验，不能依赖客户端传入 role 或 owner_id。普通成员不能踢人、分配 IP、更改房间凭证、生成房主级邀请或解散房间。

房间发现、信令、设备凭证及 Relay 授权均须绑定房间身份与有效成员资格。原有个人网络仍保持账号隔离。不同房间的设备不能因复用设备公钥、默认网络或 Relay 连接而互通。

踢出、封禁、退出、解散及改址必须撤销相关设备凭证、待投递信令与 Relay 授权，并通知其余成员移除相关 Peer。断线重连必须重新鉴权。撤销的有效时限必须可测试，不得把后台最终同步描述为即时断开。控制面离线时对过期授权采用拒绝策略，避免无限期保留跨账号访问。

踢出与封禁必须语义明确：仅移除成员后，仍持有有效密码的账号可能重新加入；需要阻止重新加入时应封禁账号或同时轮换入房凭证。不能把踢出按钮宣称为永久封禁。

## 密码与邀请

密码仅存储经适当密码哈希函数处理的结果，不能明文入库、写入日志或返回给成员。房间号是定位符，不是权限凭证。加入操作需要防猜测限速与有界请求体，并避免用不同错误泄露房间是否存在。

邀请凭证使用安全随机数，服务器仅持久化其摘要；需要有效期、撤销状态及可选使用次数限制。不能将房间密码放入链接。链接解析后必须明确目标控制面和房间，由用户确认加入；不得自动将当前账号凭证发送给链接中的任意服务器。浏览器打开链接与在应用中粘贴链接是不同能力，没有平台注册和冷启动测试不得声明一键唤起已完成。

## 必须具备的自动化测试

- 同一账号并发创建只成功一次；不同账号并发创建的网段不重叠；覆盖既有大网段重叠、地址池耗尽和迁移重入。
- 密码错误、限速、邀请过期、撤销、使用次数耗尽及并发兑换；正常加入的重试保持幂等，不重复消耗邀请次数。
- 非房主越权、跨房间读取和操作、个人网络账号隔离；同房间跨账号发现与信令允许，不同房间拒绝。
- 多设备 IP 唯一、手动地址冲突、非法地址、并发分配；退出或踢出后的旧凭证、缓存 Peer、待投递信令及 Relay 路径不得继续访问。
- 房间删除与重新创建、持久化重启、旧数据库升级、旧客户端兼容及控制面不可用时的授权边界。
- 客户端创建、密码加入、粘贴邀请、成员管理、改址、退出、解散、切换个人网络；操作失败时保留可恢复状态且不泄露凭证。
