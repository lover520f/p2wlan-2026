# 同账号多设备房间连接

房间归属和成员资格属于账号。设备分别接入，每台设备拥有独立身份、虚拟 IP、凭证和连接状态，没有“主设备”，也不绑定创建房间时使用的设备。创建者设备下线或删除不会转移房主权限。

## 用户操作

| 操作 | 影响范围 | 后续连接 |
| --- | --- | --- |
| 连接本机 | 当前设备、当前房间 | 不会连接同账号其他设备 |
| 断开本机 | 当前设备、当前房间 | 停止本机自动恢复，允许手动连接 |
| 设备菜单：断开此设备 | 指定设备、当前房间 | 服务端撤销凭证并暂停；必须手动连接 |
| 禁止此设备连接此房间 | 指定设备、当前房间 | 解除限制前禁止注册和通信 |
| 解除设备限制 / 批准此设备 | 指定设备、当前房间 | 只恢复连接资格，仍需在该设备手动连接 |
| 退出房间 | 当前账号在房间中的所有设备 | 删除成员资格，重新加入后再选择设备连接 |
| 房主解散房间 | 所有成员和设备 | 房间删除，不能恢复原房间号 |

成员可以管理自己的设备，房主可以管理所有房间设备。成员不能解除房主设置的设备限制，也不能批准待审批设备。UI 按账号分组显示设备，标明房主、成员和本机。

新安装的客户端不会因账号已有房间而自动接入。桌面端每个服务器 / 账号 / 房间有独立的本地“启动时自动连接”选项。设置不跨设备同步；退出应用保留设置，主动断开清除连接意愿，远程断开同时由服务端阻止自动注册。即使应用关闭期间被断开，下一次自动启动也不能解除暂停。

Android 当前仍使用单 VPN 连接模式；它遵循相同的设备权限、手动恢复和审批规则。桌面多房间并行能力不意味着 Android 可以同时运行多个 VPN。

## 新设备审批

房主可以开启“新设备需要房主审批”，默认关闭。开启后保留已有设备的决定，新设备第一次尝试连接会进入待审批状态，不分配可通信凭证。房主自己的新设备也需显式批准，可在登录房主账号的设备上操作。批准后仍须在目标设备点击连接。

关闭审批只影响之后的新申请，不会自动批准现有待审批设备或解除限制。设备身份按房间中的安装密钥识别，改名不会改变身份；重装或重置密钥会被视为新设备。希望防止受限设备通过更换身份重新进入时，应开启新设备审批；如需禁止某个账号，应使用账号封禁。

## 服务端模型和接口

`room_device_access` 使用 `(network_id, public_key)` 唯一身份，关联账号。状态为 `allowed`、`paused`、`blocked`、`pending`，独立于设备在线状态和临时凭证。暂停和限制保留设备 ID / IP 分配，凭证轮换或删除设备注册不会清除限制。

- `POST /api/v1/rooms/{room}/device-access`：账号请求设备接入；字段 `public_key`、`device_name`、`platform`、`resume`。只有显式手动连接传 `resume: true`，允许 `paused → allowed`；自动恢复传 `false`。此接口不会解除 `pending` 或 `blocked`。
- `POST /api/v1/rooms/{room}/device-access/{access}/{action}`：`disconnect`、`block`、`unblock`、`approve`。批准和解除限制进入 `paused`。
- `PUT /api/v1/rooms/{room}/device-policy`：房主设置 `require_approval`。
- 房间详情返回 `device_access` 和 `device_approval_required`，房间对象返回 `device_controls_version: 1`。

控制接口需要账号认证，设备凭证不能调用。服务端同时在注册、凭证校验、可见设备列表和设备互通授权处检查限制；撤销操作通知在线连接。房间通信继续使用既有的最长 30 秒授权租约，网络中断时不会无限保留过期访问权限。

命令行支持：

```sh
p2wlan room show 12345678
p2wlan room device-access 12345678 --access access-… --action disconnect
p2wlan room device-access 12345678 --access access-… --action block
p2wlan room device-access 12345678 --access access-… --action unblock
p2wlan room device-access 12345678 --access access-… --action approve
p2wlan room device-approval 12345678 --required true
```

## 升级和验证

先升级服务端，再升级客户端。数据库启动迁移自动添加设备策略表，现有房间设备初始化为允许，重复迁移不会覆盖已有决定。旧服务器不提供设备控制能力；新客户端仍可使用原有房间连接，但完整的设备管理需要新服务端。旧客户端可能只能显示通用连接错误，无法解除服务端暂停状态。

回归覆盖同账号 A/B 同时注册与独立 IP、单设备撤权不影响 B、账号退出清理所有设备、删除创建者设备保留房主、审批权限和绕过尝试、显式恢复与后台重注册的区别、本地意愿持久化和隔离，以及设备菜单操作范围。
