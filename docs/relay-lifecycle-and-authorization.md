# Relay、UDP 生命周期与房间发送授权

本次修复对应 2026-09-11 对 v0.1.157 的安卓登录、账号展示与高刷新率体验修复，发布版本为 v0.1.158。

## UDP 实例退出

PeerManager 的 heartbeat 取消回调只保存取消注册表的弱引用，不保留整个 UdpTransport、PeerManager 或 socket。旧注册表释放后，回调安全地无操作返回。新实例的回调不会让旧实例继续占用固定端口。

主 UDP reader 与辅助 IPv6 reader 都纳入同一个 JoinSet。主任务取消时，子 reader 一起取消；正常退出时等待全部 reader 回收。默认随机端口与用户配置的固定端口都遵循相同的实例生命周期。

## Relay 取票与续期

取票接口保留处理函数内的按已认证设备限流，取消外层每出口 IP 每分钟五次的共同额度。同 NAT 的独立设备和多房间实例不再争用一个小配额。

主连接续期失败后，supervisor 使用独立的五秒重试定时器。等待期间仍处理真实 EOF、路由变化和 Android 网络变化；旧票据的到期时间不会让失败任务连续立即重启。

## 多 relay 汇合

选中的 relay 仍是连接生命周期和诊断中的主节点。配置多个有效候选时，客户端在后台维持到其他候选的注册，让偏好不同或各自有不可达节点的设备能通过共同可达的节点汇合。不同候选目录必须至少存在一个双方均可访问且属于同一 network 的 relay；没有共同节点时，客户端不能凭空实现跨服务器转发。

对尚未发现路由的 peer，通过当前可用连接并发发送同一份密文。发送边界回调最多执行一次；不会为不同 relay 重新加密或分配不同 WireGuard 计数器。收到 peer 数据后记录所在 relay，后续按 peer 定向发送。路由信息只是提示，业务路径启用仍受现有 WireGuard 认证和加密往返验证约束。

某个 relay 返回 404 时清除该节点对应的 peer 路由，不把单个 hub 的缺席误判为所有 relay 均不可达。后台连接断开或取票失败后按五秒间隔重试；票据进入刷新窗口后重建辅助注册。此类连接重建仍可能有短暂丢包，不承诺无损切换。

主连接替换时，先取消并等待旧后台任务退出，再启动新连接池，避免旧重连任务在服务端通过 newest-wins 覆盖新注册。后台任务只弱引用连接池；transport 丢弃或显式 abort 时关闭全部连接。主连接 EOF 仍交由既有 supervisor 处理。

诊断中的 `selected_endpoint` 与 RTT 指主节点。`rendezvous_endpoints` 记录连接池的实际节点，`rendezvous_peer_routes` 记录观察到的 peer 路由，随主节点 Pong 更新。保持多个注册会增加连接数和各节点的续期请求，服务端容量规划应按候选节点数量计入。

## 活跃连接撤销

Go relay 为认证连接保留 device ID、credential ID 和票据 JTI。撤销快照在同一授权锁下标记并移除命中的 hub 连接，释放锁后关闭 socket。

认证注册在加入 hub 前重新检查撤销表，并与撤销扫描采用相同锁顺序。这样，在验签与发布之间到达的撤销不会被遗漏。撤销不会关闭其他设备或新凭证对应的无关连接。

## 房间发送许可

房间数据包在入队前取得 RoomSendPermit。许可包含原授权的有效期和共享撤销标记，随原始包及加密包传递。正常续租不延长已排队旧包的有效期；撤销、授权集合变化或授权对象退出使旧许可失效。

出站在 ACL 等待后、获得队列容量后复查许可。UDP 普通发送在每次 socket readiness poll 检查，受预算管理的 Direct 快速发送在最终非阻塞 syscall 前检查；relay 在命令离开发送队列、开始写入前检查。已经开始的网络写入属于在途数据，无法撤回已交给内核的字节。

默认个人网络及现有内部控制包不携带房间业务许可，保持原有语义。

## 回归验证

- 七个最初复现用例：两个 UDP socket 生命周期、续期退避、同 NAT 设备取票、跨 relay 汇合、活跃凭证撤销、ACL 等待期间房间撤权。
- device/credential/JTI 撤销与认证连接发布并发竞争。
- 房间许可不会继承后续续租或重新授权；授权对象销毁使旧许可失效。
- 真实 UDP socket 拒绝失效许可；relay 命令在队列中等待期间撤权，writer 拒绝发送。
- 两端不同候选目录经共同的第三个 relay 完成真实加密往返；连接替换后继续传输，旧连接池释放。

本机验证以 macOS 的核心测试与 loopback 集成为主；真实运营商 NAT 和 Windows/Android 网络切换仍需相应环境验收。
